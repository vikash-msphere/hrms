/*To implement interactive action buttons and progress tracking on a notification card, you must use Web Push (VAPID) with a Service Worker.
SSE cannot do this, because SSE cannot display OS-level notification cards or update them in the background. The Web Push API features built-in support for interactive actions and allows you to overwrite or update an active notification statically using a unique tag identifier.
------------------------------
## 🛠 1. Adding Quick Actions to the Notification Card
You can define up to two action buttons inside your Service Worker (sw.js). When a user clicks a button, the notificationclick event intercepts the action, allowing you to run background code (like hitting an API endpoint) without necessarily forcing your website to open.
## Service Worker Code (sw.js)
*/
self.addEventListener('push', (event) => {
  const data = event.data.json();

  const options = {
    body: data.body,
    icon: '/images/icon.png',
    // 1. Define interactive action buttons
    actions: [
      { action: 'approve', title: '👍 Approve Task', icon: '/images/check.png' },
      { action: 'reject', title: '❌ Reject', icon: '/images/cross.png' }
    ],
    // Custom payload data passed into the click handler
    data: { taskId: data.taskId } 
  };

  event.waitUntil(
    self.registration.showNotification(data.title, options)
  );
});
// 2. Handle button clicks inside the OS notification card
self.addEventListener('notificationclick', (event) => {
  const notification = event.notification;
  const action = event.action; // Tells you which button was clicked
  const taskId = notification.data.taskId;

  notification.close(); // Close the card immediately for responsiveness

  if (action === 'approve') {
    // Perform background API call without opening a browser tab
    event.waitUntil(
      fetch(`/api/tasks/${taskId}/approve`, { method: 'POST' })
        .then(res => console.log('Approved via notification action.'))
    );
  } else if (action === 'reject') {
    event.waitUntil(
      fetch(`/api/tasks/${taskId}/reject`, { method: 'POST' })
    );
  } else {
    // Default fallback (user clicked the main notification card body instead of a button)
    event.waitUntil(
      clients.openWindow(`/tasks/${taskId}`)
    );
  }
});

/* ## ⏳ 2. Showing Progress for Long-Running Tasks
------------------------------
While the Web Push API does not support smooth, fluid canvas animations inside the OS tray, it offers a strategy to show step-by-step progress using a tag property.
If you issue a new notification with an identical tag ID, the browser will silently update the text of the existing notification in place rather than creating an annoying stack of new pop-up alerts.
## Backend Update Payload Schema
As your long-running task processes on your server, your backend sends successive VAPID push payloads to the browser:

// Payload 1 (Sent at start)
{ "title": "Video Exporting...", "progress": "25", "status": "Extracting audio frames..." }
// Payload 2 (Sent 10 seconds later)
{ "title": "Video Exporting...", "progress": "60", "status": "Applying filters..." }

## Service Worker Text-Progress Logic (sw.js)
Inside your background worker, you can generate text-based loading bars using block strings (like ▓▓░░░░) to give users immediate feedback right on their desktop or mobile tray:
*/
self.addEventListener('push', (event) => {
  const data = event.data.json();
  const progress = parseInt(data.progress) || 0;
  
  // Create a visual text progress bar (e.g., 60% = "██████░░░░ 60%")
  const totalBlocks = 10;
  const filledBlocks = Math.round((progress / 100) * totalBlocks);
  const progressBar = '█'.repeat(filledBlocks) + '░'.repeat(totalBlocks - filledBlocks);

  const options = {
    body: `${progressBar} ${progress}%\n${data.status}`,
    icon: '/images/processor-icon.png',
    
    // CRITICAL: Using the same tag ensures the card updates statically in place
    tag: 'task-progress-export-101', 
    
    // Prevents the system from making an alert noise/vibration on every tiny percentage jump
    silent: true, 
    
    actions: [
      { action: 'cancel', title: '🛑 Cancel Task' }
    ]
  };

  event.waitUntil(
    self.registration.showNotification(data.title, options)
  );
});

------------------------------
## ⚠️ Important Browser Quirks & Limitations

* Action Count Limits: Desktop Chrome, Firefox, and Android support up to 2 action buttons. iOS Safari has varying support for web-push actions depending on iOS versions and requires your site to be saved as an "Add to Home Screen" PWA.
* Silent Updates (silent: true): Always mark your progress updates as silent: true. If omitted, the user's phone or computer will beep or vibrate 100 times as the percentage bar moves up, leading them to immediately block your notifications.
